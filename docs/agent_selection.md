# Existing agent selection

Research and local implementation inspection: 17 October 2026. All three repositories were cloned; comparisons are based on actual source, not only READMEs. Inspected sources remain under ignored `vendor/` directories. No candidate requires Docker for the selected local mode.

Important upstream limitation: tau-bench README explicitly warns that its bundled tasks are outdated and points to tau2-bench (now described upstream as tau3). This project **does not reuse those tasks or report tau-bench scores**. It uses the MIT agent-loop source as the existing agent, adapted to an independently authored SQLite benchmark. A current tau retail subset remains an optional later external-validity check.

The unchanged inspected upstream loop is preserved as `agent/upstream_tool_calling_agent.py.txt`; its MIT notice is in `licenses/tau-bench-MIT.txt`. The running derivative is `agent/tool_calling_agent.py`. Changes are disclosed in its header: inject a real local client instead of LiteLLM, scripted user input and termination, schema validation, process all tool calls sequentially rather than truncating to the first, resource bounds, incremental observable tracing, and a separate full-state checker. This is reuse of an existing loop, not a claim to reproduce the original tau benchmark.

The original package brings multiple cloud SDKs and an LM user simulator. We install only the dependencies used by this isolated adapted agent, pinned in `requirements.txt`; we do not claim the complete upstream package/test suite was installed or run. Our own domain tools replace tau's dictionary-backed retail tools because the requested wallet/refund workflow differs materially from tau's request-only returns.
