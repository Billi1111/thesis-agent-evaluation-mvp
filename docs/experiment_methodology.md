# Baseline methodology v1

Approved scope: 100 authored synthetic tickets, one attempt per model, no adaptation/routing. Category counts: information 15, cancellations 15, returns/refunds 25, wallet 15, shipping 10, compound 15, restricted 5. Cases vary lifecycle, amount, original payment method, balance, day-30 boundary, product eligibility, existing returns/refunds, missing records, ownership, insufficient information and compound goals; some within-category templates repeat with different conditions. This is not a standardized independent 100-template benchmark.

Expected snapshots and response characteristics are materialized before execution. The generator is independent of business-tool execution. All 100 expectations are tested with authored action plans against the real DB; these plans are checker tests and are never used as model responses or experimental results. Alternative valid tool orders are accepted. Read evidence accepts equivalent inspection tools, wallet/customer tools and authoritative order data returned by successful mutations; redundant lookups are not required. Final state and facts remain decisive. Version 2 fixtures guarantee creation before delivery, including old-return scenarios.

Smoke-test three cases before full runs. Smoke data are retained separately and never merged into benchmark totals. Once validated, freeze code, benchmark, harness, tool definitions and inference settings. Runtime manifests capture hashes, package versions, Python/platform, GGUF metadata, server build, task order/seed, and server inventory. The runner refuses unsafe resume after source/configuration changes and preserves partial trace files from interrupted attempts.

Both local models use the same llama.cpp binary, greedy temperature 0, seed 42, 8192 context, 2048 output-token cap per call (reasoning included where the server reports it), 12 model steps, 16 tool calls, 180-second call timeout, 600-second task timeout, reasoning effort low/budget 256, and concurrency one. Embedded model chat templates and quantizations differ. The GGUF files are hashed and no model weights are changed.

Model blocks are sequential because both weights cannot occupy the 12 GB GPU simultaneously. Task order is shuffled with the same seed within each model. Automatic CPU/GPU placement can differ. This is an explicit departure from the full thesis's interleaved configuration schedule and a latency confound to investigate in later runs. Server load/warm-up is outside task latency and recorded separately. Prompt cache reuse is controlled by the server; cached input tokens are retained where reported. Fresh conversations and databases prevent semantic contamination despite shared token caches.

Primary metric: passed / started non-infrastructure attempts. A pass requires expected full DB state, correct response contract/facts, inspection evidence, valid completion, and no prohibited mutation attempt. Reports separately retain DB correctness, tool errors, policy attempts, terminal states, and infrastructure failures. A model timeout is a failed attempt; connection/auth/server failures are distinct infrastructure records and stop the run after one occurrence (zero automatic retries). Observable errors are not treated as audited causal diagnosis.

The specific llama.cpp HTTP-500 message that generated output failed its native-format parser is an `invalid_model_output` attempt, retained as a model/protocol-format defect rather than a connection outage. Other server errors remain infrastructure failures. Usage for a parser-rejected generation is unavailable/partial; token totals are lower bounds when any such record exists. The zero-reasoning pilot exposed this distinction before the final run.

Per-task latency includes inference, tools and execution-loop checks, with mean/median/p95. Actual prompt/output token counts are summed; unavailable usage is null, and timeout/infrastructure records mark incomplete usage. Local API charges are $0. Electricity, GPU purchase/amortization, and effective local inference cost are unmeasured, never implied to be zero. Costs of failed attempts are retained.

Descriptive Wilson intervals accompany success bars. Paired task-cluster bootstrap (10000 resamples, seed 42) estimates differences when both models have matching task/repeat observations. Related templates and one trial limit inference; no claim of pass^5 reliability or a causal effect of parameter count is valid. Do not use these cases as a held-out thesis test set after inspecting results.
